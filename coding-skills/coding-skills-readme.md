# Coding Skills Readme

## 1. What It Does

Always-active coding standards that apply whenever code is written, edited, or discussed, regardless of language or project.

| Rule | Summary |
|---|---|
| 95% certainty rule | Asks clarifying questions on scope, output location, and constraints before writing code. |
| No broken code | Checks for conflicts with existing variables, functions, or imports before writing. |
| Minimal scope | Writes only what was asked. No unrequested refactors, renames, or added logging. |
| lowerCamelCase | All variable, function, and parameter names use lowerCamelCase, matching existing codebase style where one exists. |
| Suggestions separated | Unrequested improvement ideas are listed after the completed work, not implemented automatically. |
| Self-review checklist | Every code output is checked against all rules above before being presented. |

## 2. How To Invoke

No trigger needed. This skill is always active automatically for any coding-related request, including writing, editing, reviewing, or discussing code.

## 3. Notes

If a suggestion is offered but not requested, it will appear in a clearly separated block after the completed work. It is only implemented once explicitly confirmed.
